# pi-lcm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `pi-lcm`, a standalone Pi extension that persists every message, owns compaction with a DAG of summaries, and stores and recalls durable memories.

**Architecture:** An in-process Pi extension. SQLite (`node:sqlite`, or `bun:sqlite` under Bun) with FTS5 stores messages, summary nodes, and memories. Event handlers persist session entries, replace Pi's compaction with a DAG-rendered context window, and inject recalled memory at run start. Native Pi tools expose search, describe, expand, store, and stats.

**Tech Stack:** TypeScript, Node >=22.19, Pi extension API, `node:sqlite`/`bun:sqlite`, FTS5, TypeBox, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-12-pi-lcm-design.md`

## Global Constraints

- Node >=22.19; no native dependencies; use `node:sqlite` on Node and `bun:sqlite` under Bun.
- Host packages (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`, `@earendil-works/pi-agent-core`, `typebox`) go in `peerDependencies` with `"*"`, never in `dependencies`.
- Every Pi event handler fails open: catch, log, and return `undefined`; never throw into Pi.
- DB default: `<project root>/<CONFIG_DIR_NAME>/lcm/<project-hash>.db`; untrusted projects fall back to `~/.pi/agent/lcm/<project-hash>.db`.
- No chosen summarizer model means no pi-lcm summarization, in every mode.
- Summary coverage is `summary_messages` links built from `branchEntries` order, never seq ranges.
- One `messages` row per session entry; context-edited entries concatenate projected text.
- Summaries are created only during compaction; no background summarizer.
- Recall injects at `before_agent_start`; do not use the `context` hook.
- Thinking blocks and system messages are not stored unless `storeThinking` is true.

## Review Focus

- **`/tree` branch switch:** messages from an abandoned branch must never be covered by a summary on the new branch. Tested in Task 14.
- **Aborted compaction:** an aborted `signal` must leave no partial node and must return `undefined` so Pi compacts normally. Tested in Task 11.
- **FTS special characters:** queries containing `"`, `*`, `:`, `-`, or `OR` must not raise an FTS syntax error. Tested in Task 7.
- **Pi-generated previous summary:** a summary produced before pi-lcm was installed must survive as a `legacy` node. Tested in Task 11.
- **No model in print mode:** with `ctx.hasUI === false` and no configured model, compaction must return `undefined` without calling a model. Tested in Task 14.

- [ ] **Step 4: Implement `src/db/schema.ts`**

`SCHEMA_VERSION = 1`. `migrate(db)`:
1. `db.exec("PRAGMA journal_mode = WAL; PRAGMA foreign_keys = ON; PRAGMA busy_timeout = 5000;")` (ignore a WAL failure on `:memory:`).
2. Create `meta(key TEXT PRIMARY KEY, value TEXT NOT NULL)` if missing.
3. Read `schema_version`; if greater than `SCHEMA_VERSION`, throw `new SchemaTooNewError(current, SCHEMA_VERSION)`.
4. If missing, run migration 1 in a transaction and insert the version. If equal, return.

Migration 1 creates the tables from the spec. Use `messages.id INTEGER PRIMARY KEY AUTOINCREMENT`; `summaries.id TEXT PRIMARY KEY`; `memories.id TEXT PRIMARY KEY`. Every column the tests omit needs a default or must be nullable: `projects.created_at`, `sessions.created_at`, `sessions.updated_at`, `messages.created_at`, `summaries.created_at`, and `memories.created_at` are `TEXT NOT NULL DEFAULT (datetime('now'))`; `sessions.session_file` is nullable. `messages.role` is `TEXT NOT NULL CHECK(role IN ('user','assistant','toolResult','custom','bashExecution'))`. Add indexes on `messages(session_id, seq)`, `summaries(session_id, depth)`, `summary_messages(message_id)`, `summary_parents(parent_id)`, `memories(project_id)`. Create external-content FTS5 tables with triggers:

```sql
CREATE VIRTUAL TABLE messages_fts USING fts5(content, content='messages', content_rowid='id', tokenize='unicode61 remove_diacritics 2');
CREATE VIRTUAL TABLE summaries_fts USING fts5(content, content='summaries', content_rowid='rowid', tokenize='unicode61 remove_diacritics 2');
CREATE VIRTUAL TABLE memories_fts USING fts5(content, tags, content='memories', content_rowid='rowid', tokenize='unicode61 remove_diacritics 2');
```

Add `ai`, `ad`, and `au` triggers for each table, inserting `new.rowid` (or `new.id` for messages) and using the FTS5 `'delete'` command on delete/update.

- [ ] **Step 3: Implement `src/compact/chunk.ts`**

Packing rule:

1. Start a chunk. Add messages one at a time. If adding the next message would make `tokenCount > budget` and the chunk already has at least one message, add that message anyway (the crossing message), then close the chunk. This keeps the message with the context that precedes it.
2. Before closing a chunk, add every following `toolResult` message so a tool call and its results never split.
3. If the number of chunks exceeds `maxChunks`, recompute with `budget = min(max(budget, ceil(totalTokens / maxChunks)), modelLimit)` and repack with the same rules.
4. If the repacked count still exceeds `maxChunks` because `totalTokens > maxChunks * modelLimit`, return one chunk containing every message with `oversized: true`.
5. If any packed chunk's `tokenCount > modelLimit`, return one chunk containing every message with `oversized: true`.
6. A single message larger than `budget` forms its own chunk; if it is larger than `modelLimit`, the result is one oversized chunk.
